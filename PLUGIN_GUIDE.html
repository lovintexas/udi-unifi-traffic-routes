UniFi Traffic Routes

IoX integration for selected UniFi Network controls and monitoring: traffic routes, Wi-Fi SSIDs, designated clients, switch ports, PoE, and user-created firewall policies.
Local UniFi APIIoX / eisyPG3xLocal control

Overview

The plugin presents useful UniFi Network objects as native IoX nodes so they can participate in IoX programs, UD Mobile, status displays, and automation.

Traffic RoutesMonitor and enable/disable discovered UniFi Traffic Routes.
Wi-Fi SSIDsMonitor and enable/disable configured UniFi Wi-Fi networks from IoX.
Selected ClientsMonitor blocked state as the primary IoX state and online state as a secondary state for clients placed in the UniFi IoX client group.
Switch PortsMonitor physical link state and negotiated link speed.
PoE PortsMonitor configured PoE state as the primary IoX state, link state, and power, with standard On/Off control and PoE Cycle.
Firewall PoliciesMonitor and enable/disable user-created policies while excluding predefined UniFi policies.

UniFi Account Permissions

Configure the dedicated account in the UniFi console with:

  • Account Type: Admin
  • Network: Full Admin
  • Local Account Only: Enabled

The plugin requires Network administrative access because it performs both read and write operations, including Traffic Route control, client Block/Unblock, PoE control, and firewall policy enable/disable.

Permissions for other UniFi applications such as Protect, Access, Talk, and Control Plane are not required by this plugin.

Client selection

Create a UniFi Network client group named IoX (type CLIENTS) and add only the clients that should appear as IoX client nodes.

Startup

Read PG3x parameters→Local UniFi login→Discover objects→Create/update IoX nodes

If initial authentication fails, the controller is marked unavailable and the plugin does not continuously retry the login. Correcting the custom parameters or restarting the plugin initiates another attempt.

How Status Is Determined

Wi-Fi SSIDs

Enabled status reflects the current UniFi WLAN configuration. Enable and Disable commands change only the SSID's enabled state while preserving the existing WLAN configuration.

Clients

Online status comes from UniFi's active-station data. A client absent from that list is reported offline.

Blocked status is tracked independently using UniFi's current blocked-client history. A blocked client normally disappears from the active-station list, so a node can correctly show Blocked: True and Online: False.

Block and Unblock commands are followed by delayed readback of UniFi's actual blocked-client state rather than an assumed optimistic change.

PoE

PoE Enabled represents configured state. A port configured for PoE may not be actively delivering power when no powered device is present. PoE commands use delayed switch readback; PoE Cycle turns power off, verifies it, waits, restores automatic PoE, and verifies again.

Firewall policies

Only policies for which UniFi reports predefined = false are exposed. The plugin changes only the enabled state; it does not edit matching, action, networks, ports, or other policy content.

Polling & Discovery

The current installation uses approximately 60-second short polling for routine status and 300-second long polling for discovery. Commands requiring verification perform their own delayed readback.

  • Short polling refreshes traffic routes, Wi-Fi SSIDs, selected clients, firewall policies, and switch ports.
  • Long polling discovers newly available objects.
  • Client nodes are created only for members of the UniFi IoX client group.

Design Boundaries & Limitations

  • No general UniFi configuration editor. The plugin intentionally exposes a small set of well-defined controls.
  • No ordinary switch-port administrative disable. Current UniFi behavior changes several network/VLAN-related fields rather than exposing a simple safe enable flag, so this control is intentionally omitted.
  • Firewall editing is restricted. Only user-created policies are exposed, and only their enabled state can be changed.
  • Client scope is explicit. Only members of the IoX client group are managed as client nodes.
  • Online and blocked are separate. Unblocking permits reconnection but does not force a client to associate or transmit immediately.
  • Discovery is additive. Removing an object from UniFi or from a group may leave an existing IoX node until the plugin/node configuration is rebuilt; automatic stale-node deletion is not currently implemented.
  • API compatibility is version-sensitive. The plugin uses local UniFi Network endpoints observed and tested in the development environment; Ubiquiti may change these endpoints.
  • TLS certificate verification is disabled for the local UniFi connection in the current implementation.

Security Notes

  • Use a dedicated local UniFi account and a strong unique password.
  • Do not publish credentials, session cookies, CSRF tokens, or captured authentication headers.
  • PG3x DEBUG logging may expose custom parameters. Normal operational logging should be kept below DEBUG after development.
  • After development where credentials may have appeared in debug output, rotate the dedicated UniFi password.

Current Development Status

The feature set has been tested interactively against the local UniFi installation, including Traffic Route control, Wi-Fi SSID discovery and enable/disable, switch-port discovery, PoE control with verified readback, user-created firewall-policy enable/disable, client Block/Unblock, and independent blocked-state reporting.
